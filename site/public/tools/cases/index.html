02
业务判断

先讲原始流程有多痛，再讲为什么值得优先做

  • 原始流程：清单拿旧模板改、工商与涉诉信息人工逐家查、访谈笔录手工整理、报告初稿逐章从零写、每收一批底稿改一轮、格式靠肉眼调——每一环都是搬运式重复劳动，却又都要求准确、可溯源。
  • 真实问题：①一份报告几十项问题，每项都要「核查程序 + 底稿证据 + 结论」三件套，写作时间大部分花在搬运而非判断；②底稿分批到达、报告反复改版，版本极易串；③跨项目经验散落在个人脑中，新人无法复用历史口径。
  • 为什么优先做：尽调是非诉业务的入口与基座——IPO、并购、投融资都从它开始；流程规整、模板成熟，是 AI 工序化回报最高的场景；这条线建成，问询回复、合同审查等工序都能接在后面。
  • 砍掉了什么：AI 不下最终法律结论——每项问题的结论口径、风险分级、访谈现场的追问与判断，一律留给律师；AI 不直接向客户发问、不自行调取或上传底稿，材料流转由人组织。
03
方案设计

为什么用 AI，而不是更简单的方案

  • 替代方案为何不行：模板加宏解决不了「读懂底稿再改对应章节」；外包初稿守不住保密与口径一致；通用聊天机器人没有数据源、没有版本纪律，也不会主动说「这项我没有底稿」。只有把律师的判断规则写进指令、把检索与核验接到数据源，产出才能既快又可溯源。
  • 架构（三层基础设施 × 六阶段调度）：指令层——全局指令与项目指令双层叠加；技能层——委托前分析、清单起草、访谈笔录定稿、报告起草与迭代、证券知识库检索；数据层——企查查、天眼查、元典、见微等经 MCP 直连。主代理按六阶段调度，子代理各管一段，结果汇入同一份版本化报告。

关键取舍与真实约束（写进指令，不靠自觉）

  • 事实只能来自公司资料与经核验的公开信息：AI 不得凭记忆填写企业信息，不得据单份报告推断关联、控制关系或实控人对外任职——不确定处一律【】占位。
  • 每项事实标注底稿来源（文件名 + 页码 / 条款号）；未取得底稿的问题写「待补充」，不推测。
  • 法律结论五级分级（明确 / 通说 / 存在争议 / 待核验 / 待公司确认）；成文正文不内联标注，以批注提示，保持对外文件流畅。
  • 版本纪律：始终以最后确认版为唯一底稿，每阶段出一个版本号，不覆盖前版；文件按统一规范命名。
  • 敏感材料本地处理（OCR、文件解析不经第三方上传）；对外交付前关键词检索逐一核验脱敏。

Q1这个需求是怎么来的？为什么先做它？

不是来自某一次布置，而是所里每个尽调项目反复出现的最高频痛点：清单改模板、信息人工查、初稿逐章写、底稿到了改一轮。它同时满足两个条件——值钱（尽调是非诉业务入口，业务量最大）且好做（流程最规整、模板最成熟，是 AI 工序化回报最高的场景）。这条线建成，问询回复、合同审查都能接在后面。

Q2AI 之前人工也能做，区别在哪？

都能做——过去几十年律师就是这么做的。区别在成本结构与确定性：人工是线性成本，每个项目重新花一遍人日；生产线一次搭建、边际成本极低地复用。人工质量靠个人经验与自觉，生产线把纪律写进指令（事实必须可溯源、不确定必须占位、版本必须留痕）。「核查程序—底稿—结论」三件套一个不少，省掉的是搬运时间。

Q4这一单怎么拿到的？客户为什么选你？

来自我在事务所讲授的 AI 课程（连续两年：AI 合同审查与起草、AI Agent 工作范式）——课后团队形成共识：有必要把 AI 系统引入日常业务。选我的原因：自己用得真好（本页案例全部是我本人项目的真实运行记录）、工具链熟练（模型、智能体、MCP、知识库全链路）、项目做得多（8 年资本市场、5 单 IPO 签字，知道业务真正的痛点在哪）。

Q5为什么以个人身份申报，不以公司名义？

这条生产线及其全部资产——指令库、技能、知识库、代码仓库、本站——都是以我个人名义搭建、维护并公开的（站点与 GitHub 均为个人账号，WorkBuddy 技能以本人名义发布）。律所是平台与客户，工具体系是个人作品；以个人身份申报，资产与责任都清晰。

Q6把 AI 拿掉，这件事还能不能成？

能做，但完全不是同一件事：培训还能讲，只是从「可复制的工作方式」退化为经验分享；尽调报告还能出，只是回到人日堆砌、版本靠肉眼、口径靠记忆。AI 拿掉后，变化的不是「能不能」，而是成本结构与可复制性——这正是本案例的价值所在：把一个人的产能和经验，变成一支团队可复用的基础设施。

CASE 05底稿 / 批处理

非结构化底稿批处理：批量识别与原位翻译

痛点
152 张手机拍摄的货运单据（手写日期、倾斜、重复拍摄）要出结构化台账；21 份英文贸易单据（含盖章扫描页）要交中文译文，但原件一个字节不能改。
做法
识别：152 张 ÷ 10 = 16 个图像识别子智能体分 3 批并行，每张抽 19 个字段并标注存疑，主代理合并去重、工商库核验收货方、日期规范化、自动出台账。翻译：自研 PDF 英→中覆盖式翻译，输出「原件页在前 + 译文页在后」，页面级拼接并程序化校验原件字节一致。
效果
152 张全程约 40 分钟（实测，含三轮验收）；21 份全部交付、原件零改动（程序校验）。
口径与印证
耗时为实测、文件数为实际交付；多智能体并行调度规则见 《法律业务通用指令》第十三章。

展示成果的同时把边界讲清楚，才是可审计的 AI 落地。

客户数据保密怎么处理？

敏感环节（OCR、文件解析）完全本地运行，不经第三方上传；境外模型只接触脱敏后的结构化字段与公开信息；对外产出前以关键词检索逐一核验脱敏效果——本页即按该流程交付。

AI 幻觉怎么控制？

法条、案号、企业信息一律回官方来源或 MCP 直连数据源核验，不得凭记忆填写；法律结论实行五级确定性分级；无法核验的如实标注「待核验」或以【】占位，不以推测填充。

「95% 由 AI 完成」的边界在哪？

95% 指工序产出（初稿、检索、核验、格式）；签字、事实与法律判断、访谈追问、与客户和监管的沟通、冲突取舍——这 5% 始终在律师。页面所有「95%」口径均为此义。

为什么不用更简单的方案？

都试过：模板加宏改不了「读懂底稿再改对应章节」；外包初稿守不住保密与口径一致；通用聊天机器人没有数据源也没有版本纪律。工具造不出来，就只能回到人日堆砌——所以律师为自己造工具。
