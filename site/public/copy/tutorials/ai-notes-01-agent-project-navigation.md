# AI札记01｜别指望一个Agent一次做完一个大项目

我最近越来越有一个感觉：

**复杂项目，不应该幻想靠一个Agent、一条提示词，一次性从头做到尾。**

刚开始用AI的时候，很容易有这种期待：

把全部材料交进去，把任务说清楚，然后让Agent自己运行几个小时，最后回来拿一个完整成果。

听起来很理想。

但真正做复杂项目以后会发现，很多工作根本不是这样推进的。

项目在往前走的过程中，人会不断发现新的问题，补充新的材料，改变原来的判断，甚至重新确定下一步应该往哪里走。

所以我现在更愿意把Agent看成一个长期参与项目的执行者，而不是一个接到命令以后就消失几个小时、最后交答案的黑盒。

## 人还是要掌握项目的方向

比如做一个尽调项目。

一开始可以先把项目目标、尽调清单、客户资料和历史模板交给Agent，让它理解整个项目。

但接下来并不是一句：

“请完成全部尽调并出具最终报告。”

然后就不管了。

更现实的做法是：

先让Agent整理资料；

我看一下它对项目的理解有没有偏；

再处理历史沿革；

发现某次股权转让存在问题，就单独把这一块切出来继续查；

处理完以后，再进入重大合同；

遇到一个特殊法律问题，再让它去法规库、案例库或者自己的知识库里研究；

等资料逐渐完整以后，再一章一章形成报告。

整个过程其实是：

**人掌舵，Agent执行。**

## 大项目不是“一次任务”，而是一连串不断变化的小任务

这一点很重要。

复杂项目最开始的时候，我们自己也未必知道最后会遇到什么。

有些问题只有真正开始整理材料以后才会出现。

有些风险只有把不同文件放在一起比较以后才会发现。

有些原来认为很重要的问题，做到一半才发现其实没有那么重要。

所以提前设计一个完美提示词，让Agent严格按照最初计划一直执行到底，未必是最好的方式。

更合理的是先确定大方向，然后随着项目推进不断调整。

可以把一个大项目理解成：

**总体目标不变，但具体路径一直在动态变化。**

Agent完成一段，人检查一段。

方向正确，就继续。

方向偏了，就马上纠正。

发现新的问题，就把问题切出来单独处理。

这其实和我们现实中带一个项目组没有太大区别。

## 不要怕“打断”Agent

有时候我们会觉得：

既然已经把任务交给Agent了，就应该让它自己完整做完，否则好像没有发挥AI自动化的价值。

我现在反而觉得不是这样。

复杂项目里，主动介入本身就是工作的一部分。

如果Agent已经做了20%，你发现方向错了，就应该立即纠正。

没有必要为了所谓的“自动运行”让它把剩下80%全部做错。

AI真正节省的不是人与项目完全脱离的时间，而是大量具体执行工作的时间。

人的价值仍然在于：

判断方向；

发现异常；

决定优先级；

告诉Agent哪些事情值得继续深挖；

决定什么时候停止。

## 一个Agent也不一定承担整个项目的所有事情

项目推进过程中，还可以继续切任务。

比如同一个IPO项目：

一个任务整理客户资料；

一个任务核查历史沿革；

一个任务检索审核案例；

一个任务核验法规；

一个任务起草问询回复；

最后再换一个Agent做独立复核。

这些任务最后仍然属于同一个项目。

真正需要保持一致的是：

**项目背景、事实基础、最终目标和文件体系。**

而不是强迫所有工作必须由同一次对话、同一个Agent一次完成。

## 所以，我越来越不追求“一条提示词解决一切”

一条提示词把复杂项目从头跑到尾，看起来很酷。

但真正进入专业工作以后，我更看重的是：

**能不能在整个项目周期里持续和Agent沟通、纠偏、切任务，让它始终沿着正确方向往前走。**

这可能才是人与Agent长期协作更现实的状态。

不是：

**人布置任务 → AI完成项目。**

而是：

**人确定方向 → AI执行 → 人检查 → 调整方向 → AI继续执行。**

循环往复，直到项目真正完成。

## 最后一句

复杂项目里，Agent不是自动驾驶。

它更像一个执行能力很强的项目成员。

**方向盘始终应该在人手里。**

真正会用Agent，不是想办法让自己彻底离开项目，而是知道什么时候该放手让它做，什么时候必须介入，什么时候应该把任务重新切开。

这可能比寻找一条“万能提示词”更重要。
