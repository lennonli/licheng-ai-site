# 让 AI 直接帮我搭建第二个网站

请你作为网站项目负责人，按照我现有网站 `ai.licheng.uk` 的基本方式，直接帮我搭建一个全新网站。

## 二、你要直接完成的工作

请按以下顺序执行：

1. 先读取并检查现有 `ai.licheng.uk` 的建站方式，了解它的页面结构、字体、颜色、响应式设计、GitHub管理和Cloudflare发布方式。
2. 不修改现有网站，不删除现有文件，不影响现有域名和线上内容。
3. 为新网站建立独立项目和独立 GitHub 仓库。
4. 使用稳定、简单、适合内容网站的方案搭建。原则上沿用现有网站使用的 VitePress + GitHub + Cloudflare Pages 方式。
5. 根据我的内容完成首页、菜单、页面、文章、图片、表格及移动端布局。没有提供的事实、名称、数字或图片不得自行编造。
6. 做好网站标题、简介、导航、搜索、页面链接、手机端显示和基本 SEO 设置。
7. 在本地完成构建和链接检查，修复发现的问题。
8. 将网站上传到 GitHub。
9. 配置 Cloudflare Pages 自动发布；如果现有环境已有可复用的发布流程，优先沿用，不要另起复杂系统。
10. 绑定我的自定义域名；如果域名还没有准备好，先使用 Cloudflare 临时网址发布。
11. 发布后实际打开网站，检查首页、每个菜单、图片、手机端和自定义域名是否正常。
12. 最后把网站网址、GitHub仓库、完成内容和仍需我操作的事项一次性告诉我。

## 三、请遵守这些要求

- 不要只给我代码或教程，要直接替我完成。
- 不要让我复制粘贴大量命令。
- 不要修改或覆盖 `ai.licheng.uk`。
- 新网站必须与原网站分开管理，不能把两个网站混在一个仓库里。
- 不要把密码、API Token、身份证号、客户底稿或其他隐私信息写入代码仓库。
- 需要我登录 GitHub、Cloudflare 或域名服务商时，明确告诉我“现在请我登录”，等我完成后继续。
- 如果需要创建仓库、项目或域名记录，可以直接完成；如果平台必须由我确认，告诉我只需要点击哪里。
- 发现页面内容、主体名称、金额、日期或图片资料不确定时，标注【待确认】，不要自行编造。
- 如果内容属于法律、客户或未公开项目资料，默认先做脱敏；未经我确认，不要公开发布。
- 不要为了追求复杂功能而增加数据库、登录、支付或后台管理。第一版先做成稳定、好看、能访问的网站。
- 如果遇到技术错误，先自行排查并修复；只有确实需要我的账号权限、验证码或业务决定时才询问我。

## 四、网站设计要求

在没有特别说明时，请采用以下默认设计：

- 页面简洁、专业、容易阅读；
- 电脑端和手机端都能正常显示；
- 首页第一屏能看懂网站是做什么的；
- 菜单名称清楚，不能出现英文占位词；
- 内容较多时使用分类卡片、目录和搜索；
- 链接、按钮和文字有足够对比度；
- 外部网站链接在新窗口打开，并注明其用途；
- 页面底部保留版权和联系方式位置；
- 不使用与网站内容无关的装饰图片。

## 五、遇到资料不足时的处理方式

- 缺少网站名称：使用【网站名称】，同时继续搭建结构。
- 缺少域名：先发布 Cloudflare 临时网址。
- 缺少正文：先搭建页面框架，使用【待补充内容】，不要编造文章。
- 缺少图片：先使用简洁的文字和 CSS 版式，不要随意下载不明图片。
- 缺少 GitHub 或 Cloudflare 权限：完成本地项目和配置准备后，列出我需要完成的最少操作。
- 原网站的内容或结构不能直接复制到新网站，除非我明确授权。

如果网站已经上线，请直接给我可点击的网址，不要只告诉我代码保存在哪里。

通常我只需要：

1. 告诉你网站名称、用途和内容；
2. 在需要时亲自完成 GitHub、Cloudflare 或域名服务商的登录、验证码和授权；
3. 审阅你上线后的网址。

现在请先用编号方式复述你对网站名称、页面、内容、域名和发布范围的理解，然后直接开始搭建。不要先给我编程课程，也不要要求我自己敲代码。
