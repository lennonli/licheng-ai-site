# 别打断它：智能体"辅助对话"的律师用法

> 所内AI工具使用教程系列（三）
> 撰写：李成
> 日期：2026年8月21日
> 适用工具：Claude Code `/btw`、Codex `/side`、ZCode 辅助对话

---

## 一、先说一个真实会遇到的困境

你让智能体通读目标公司三年的四十份股东会、董事会决议，出一份瑕疵清单。它跑到第二十份的时候，你忽然想起一件事：前面某一份决议里，好像出现过"委托持股"的字样。

这个念头很要紧——如果真有代持，整个股权清晰性的核查路径都要改。但你面临一个尴尬的选择：

**打断它。** 按下停止，问一句，然后让它接着跑。问题是它已经读进去的二十份材料的"记忆"往往会被这一下搅乱，轻则重复劳动，重则前功尽弃。

**忍住不问。** 等它跑完再说。可万一真有代持，这四十份的清单就白出了一遍。

**另开一个对话问。** 新对话对这四十份材料一无所知，你得重新把材料喂一遍——时间、token、和你的耐心一起烧掉。

这三条路都不好走。**辅助对话，就是为这个场景造的第四条路。**

---

## 二、它是什么：法庭上的耳语

打个律师听得懂的比方。

主对话，相当于**法庭笔录**。你说的每一句话、智能体的每一次回答、它读过的每一份文件，全部计入记录，全部构成后续判断的依据，也全部占用它有限的"注意力"（上下文窗口）。

辅助对话，相当于**你和助理在辩护席上的低声交换**。你转过头问一句"刚才那份证据的页码是多少"，助理答一句，你点点头，庭审继续。这句话**不进笔录**，不影响审判长的判断，也不改变案件走向。

技术上就是这个意思：辅助对话看得见主对话的全部内容，但它的一问一答**不写回主对话历史**。主任务的思路不被打断，上下文不被污染，成本也几乎可以忽略。

### 三个工具里它叫什么

| 工具 | 名称 | 调用方式 |
| --- | --- | --- |
| Claude Code | 侧问 / side question | `/btw 你的问题` |
| Codex | 侧边对话 / side conversation | `/side 你的问题`，或先打 `/side` 开一个空线程 |
| ZCode | 辅助对话 | `/side` 或 `/btw`，也可直接在副屏区域提问 |

名字不同，内核是同一件事。ZCode 索性把两个命令都做了，你在里面打 `/side` 和 `/btw` 效果一样。

## 三、律师能拿它干什么：六个具体场景

下面每一条都配了可以直接照抄的问法。为免泄密，例子均作脱敏处理。

### （一）问出处，不打断

这是最高频的用法。智能体正在长跑，你想确认它读到过什么。

> `/btw 你目前读过的决议里，有没有出现"委托持股""代持""代为持有"这类表述？分别在哪几份文件的第几条？`

它会从已经读进去的内容里直接答你。如果确实有，你再决定是不是值得中断；如果没有，主任务继续跑，你的疑虑也放下了。

### （二）核对它自己的口径

智能体最容易在几组近义概念上打滑：认缴与实缴、股权转让与增资、保证期间与诉讼时效、解除与终止。等它写完一整份文件你再发现，返工量很大。

> `/btw 你刚才写的注册资本那一段，用的是认缴口径还是实缴口径？依据的是哪一份材料的哪一处？`

**注意一个反直觉的地方：在辅助对话里纠正它，主线是不会改的。** 这一问一答不进主对话，它的"认知"没有被更新。你确认它错了，必须回到主对话里正式说一遍。辅助对话只负责让你**发现**问题，不负责**解决**问题。

### （三）先探路，再决定要不要中断

中断是有代价的。与其贸然打断，不如先花五秒钟问一句它的打算。

> `/btw 你现在这个思路，是打算把违约条款和解除条款分开写，还是合并成一条？`

方向对，让它跑完；方向偏，再中断也不迟。这一句探路的成本，比一次错误的中断低得多。

### （四）在等待里做自己的判断

智能体跑长任务的十几分钟，通常是被浪费掉的。辅助对话可以把这段时间用起来——问一些"关于本案"但不影响主线的问题。

> `/btw 按你目前掌握的交易结构，如果违约金定在日万分之五，对我方（转让方）是偏高还是偏低？`

它答的是判断，不是文件，不会打乱主线正在写的东西。

### （五）交接前的自检清单

这一条对多人协作和跨工具接续特别有用。

> `/btw 把你目前认定为已核实的事实、和还没有核实的事项，各列一份清单。`

为什么必须用辅助对话问？因为**如果你在主对话里问这句话，这句话本身会成为上下文的一部分**，智能体接下来很可能围着你要的清单打转，甚至开始迎合清单去凑事实。辅助对话没有这个副作用——你拿到了一张体检报告，而病人不知道自己被体检了。

### （六）随口的术语与口径回忆

> `/btw 我们这个对话前面约定的管辖法院是写的哪一家来着？`
> `/btw 你前面提到的那份补充协议，文件名叫什么？`

这类问题本身没什么技术含量，但如果丢进主对话，就是白白往上下文里塞垃圾。攒到辅助对话里问，主对话干干净净。

## 四、四条红线：律师必须知道的边界

这一节比上一节重要。用错了，代价是执业风险。

### （一）它在"回忆"，不在"检索"——法条不能信

**这是对律师最要命的一条。**

Claude Code 官方文档写得很直白：侧问"只能从已经在上下文里的内容作答。回答侧问时，Claude 不能读文件、不能执行命令、不能搜索。"（原文：*No tool access: side questions answer only from what is already in context.*）

Codex 的 `/side` 同理，把继承来的历史当作"仅供参考"（reference-only），并且在侧边模式下把绝大多数斜杠命令都藏起来，只留 `/copy`、`/diff`、`/mention`、`/status`。

翻译成人话：**辅助对话里蹦出来的法条编号、司法解释条款、案号、企业工商信息，一律不能直接用。** 它没有去查任何数据库，它是在凭"印象"作答——而这正是AI幻觉的高发区。

正确做法：辅助对话只用来问"**这个对话里已经有的东西**"。凡是需要向外求证的，回到主对话，让它调用北大法宝、企查查或者去官方网站核，并且要它给出条文出处或案号。

### （二）它不留痕，不能当底稿

Claude Code 的终端版本，辅助对话的线程只存在内存里，按 `x` 可以清空，**退出程序就没了**。VS Code 扩展（v2.1.227 及以上）的面板会保留得久一些。Codex 官方把 `/side` 直接称为"临时（temporary）"侧边聊天，社区里还在提"把 side 聊天存进会话日志""保留 side 聊天历史"的需求（openai/codex issue #20262、#30176）——**功能被提出来，恰恰说明现在没有**。【待核验：Codex 与 ZCode 辅助对话的本地留存与导出规则，以各自后续官方文档为准】

对律师的含义：**辅助对话不构成工作底稿。** 你在里面问出来的关键结论，如果有价值，必须手动带出来——

- Claude Code：在答案浮层里按 `c`，复制为原始 Markdown，粘进你的工作笔记；
- 更重要的结论：按 `f` 把这次问答分叉成一个正式会话，那个会话有完整工具权限，可以接着核实、接着写文件，原会话在 `/resume` 里照样保留（仅本地会话可用）；
- Codex：`/side` 模式下保留了 `/copy`，同样可以把内容取出来。

### （三）保密义务不因为"随口一问"而降低

辅助对话同样是把内容发给模型的。它省的是**上下文占用**，不是**数据传输**。客户名称、身份证号、未公开交易信息、诉讼策略，该脱敏的照样要脱敏，该走本地处理的照样走本地。不要因为它看起来像"私下嘀咕"就放松。

### （四）它看不见"正在写的那一句"

Claude Code 明确说明，侧问能看到目前为止的全部对话，"除了 Claude 正在写的那一条回复"。所以，如果你想问的恰恰是它此刻正在生成的内容，辅助对话答不上来——那就是该老老实实等一等，或者干脆中断。

## 五、和其他机制的分工：别用错工具

Claude Code 官方文档里有一句概括得极准的话：

> **`/btw` 是子代理的反面：它看得见你的完整对话但没有工具；子代理有完整工具但上下文为空。**

把这句话展开，就是一张分工表：

| 机制 | 看得见什么 | 能做什么 | 律师什么时候用 |
| --- | --- | --- | --- |
| **辅助对话** | 本次对话的全部内容 | 只能说话，不能动手 | 问**它已经知道**的事：出处、口径、进度、打算 |
| **子代理** | 不继承本次对话，只拿到你交办的任务 | 完整工具，能查能读能写 | 让它**去查新东西**：核法条、查主体、跑一份独立核查 |
| **分叉 / 分支** | 继承父对话 | 完整工具 | 一个岔路值得认真走下去时，把它变成正式会话 |
| **压缩（/compact）** | —— | 压缩上下文 | 对话太长、快撑不住时 |
| **中断** | —— | —— | 方向确实错了，必须立刻纠偏 |

最常见的误用，是拿辅助对话当子代理使——问它"《公司法》第八十八条现在的表述是什么"。它会答，答得还挺像，但那是回忆不是检索。**问已知，用辅助对话；查未知，用子代理。**

## 六、三个工具的操作对照

以下均以各自官方文档／官方仓库为准，核验日期 2026年8月21日。

### （一）Claude Code `/btw`

| 项目 | 说明 |
| --- | --- |
| 调用 | `/btw 问题`；不带问题则重新打开最近一次侧问（v2.1.212 起，此前必须带问题） |
| 可见范围 | 你的消息、Claude 的回复、它已获取的工具结果；不含正在生成的那条回复 |
| 侧问互见 | 每次提问会重放最近 20 轮侧问，直到你清除 |
| 主对话影响 | 问答永不进入对话历史 |
| 工具权限 | 无 |
| 追问 | 终端浮层内不能追问，需再发一条 `/btw`，或按 `f` 分叉；VS Code 扩展（v2.1.227+）在面板里可以直接追问 |
| 并发 | Claude 正在工作时可以用，不打断主回合 |
| 成本 | 提示缓存热的情况下，基本只花答案本身的钱 |
| 留存 | 终端版存于内存，退出即消失；VS Code 面板线程可跨窗口重载保留 |

**浮层快捷键**（答案出现后）：

| 按键 | 作用 |
| --- | --- |
| `空格` / `回车` / `Esc` | 关闭答案，回到输入框 |
| `↑` / `↓` | 滚动答案 |
| `←` / `→` | 在本次与更早的侧问答案之间切换（需 v2.1.187 及以上） |
| `c` | 把答案复制为原始 Markdown（**别用鼠标选，鼠标选到的是终端折行后的排版**） |
| `f` | 分叉成新会话，继承父对话及本次问答，带完整工具权限（仅本地会话） |
| `x` | 清空上方显示的更早侧问列表 |

当前答案上方会灰显最近 5 条更早的侧问，并标出更早还有多少条。它们同样不进对话历史。

### （二）Codex `/side`

| 项目 | 说明 |
| --- | --- |
| 调用 | `/side` 开一个空的侧边线程，或 `/side 问题` 直接提问 |
| 官方描述 | "Start a temporary side chat without interrupting the main chat"（开一个临时的侧边聊天，不打断主聊天） |
| 性质 | 临时分叉（ephemeral fork），不打断主线程 |
| 可见范围 | 继承主线程历史，但按"仅供参考"处理 |
| 工作区 | 除非你在侧边对话里明确要求，否则回避改动工作区 |
| 可用命令 | 侧边模式下只保留 `/copy`、`/diff`、`/mention`、`/status`，其余隐藏 |
| 退出 | `Esc` 或 `Ctrl+C` 回到主线程 |
| 界面 | 目前是切换式而非分屏，社区正在提分屏（issue #34498）、"提升为主对话"按钮（#36650）、多标签切换（#22307）等需求——**这些是待实现的建议，不是现有功能** |

需要提示一点：官方《斜杠命令参考》页确实收录了 `/side`，但只有上面那一句话。上表中关于**工具边界、可用命令、退出方式**的细节，来源是实现该功能的 PR #18190，而非成文文档；App 命令页的收录缺失另有 issue #24817 在跟进。这意味着这些细节随版本变动的可能性较大，**以你本机 `/help` 的实际输出为准**。

### （三）ZCode 辅助对话

| 项目 | 说明 |
| --- | --- |
| 首次上线 | v3.4.2（2026年7月22日）："支持辅助对话，可在副屏继续提问" |
| 命令支持 | v3.6.5（2026年8月3日）："新增 `/side` 和 `/btw` 命令，用于打开侧边辅助对话" |
| 多标签 | 同为 v3.6.5：辅助对话支持同时打开多个标签页 |
| 相关便利 | v3.4.2 同时支持"选中文本快速加入上下文" |

ZCode 的官方定位是"智能体开发环境"（Agentic Development Environment，ADE），围绕 GLM-5.3 构建的桌面端工作环境，账户体系接 BigModel。它把 `/side` 和 `/btw` 两个命令都做成了打开辅助对话的入口——从 Claude Code 或 Codex 转过来的人，不用改肌肉记忆。

## 七、可以直接照抄的九句话

存进你的备忘录，遇到对应场景直接改词就能用。

**核查类**

1. `/btw 你目前读过的材料里，有没有出现〔关键词〕？在哪几份文件的什么位置？`
2. `/btw 你刚才那段结论，依据的是哪一份材料？请给出文件名和条款位置。`
3. `/btw 你把〔概念A〕和〔概念B〕区分清楚了吗？分别用在了哪几处？`

**过程控制类**

4. `/btw 你现在做到哪一步了？还剩几件事？`
5. `/btw 你接下来打算怎么处理〔某条款〕？先说思路，不用动文件。`
6. `/btw 我如果现在中断你，已经完成的部分会不会丢？`

**交接与复核类**

7. `/btw 把你已核实的事实和尚未核实的事项，各列一份清单。`
8. `/btw 到目前为止，你有没有哪一处是靠推断而不是靠材料得出的结论？`
9. `/btw 这份文件里，还有哪些地方需要向客户确认才能定稿？`

第 8 句尤其值得养成习惯。让智能体自己指认"哪里是推断"，是成本最低的一道防线，而且因为不进主对话，它没有动机去粉饰。

## 八、四个常见误区

**误区一：以为它能帮你查资料。**
不能。它没有工具权限。要查法条、查工商、查案例，回主对话，或者派子代理。

**误区二：以为在辅助对话里纠正了，主线就改了。**
不会。辅助对话是只读的旁支，你的纠正不会写回主线。发现问题后，必须回主对话正式提出。

**误区三：拿它当 `/compact` 用。**
辅助对话省的是"不往上下文里加东西"，不是"把已有的东西压掉"。对话真的太长了，该压缩还得压缩。

**误区四：把辅助对话的产出当成果留存。**
它随时会消失。有价值的内容，`c` 复制出来，或者 `f` 分叉成正式会话——别指望回头还能找到。

---

## 九、一句话总结

**辅助对话解决的不是"AI不够聪明"，而是"我不想为了问一句话，付出打断它的代价"。**

它是一个上下文管理工具，不是一个能力增强工具。用好了，你能在长任务运行的全过程里保持对它的监督，而不必在"盲等"和"频繁打断"之间二选一——这恰恰是律师做质量控制时最需要的姿势。

但也正因为它只会"回忆"不会"查证"，凡是要写进法律文书的东西，一个字都不能从辅助对话里直接拿。
