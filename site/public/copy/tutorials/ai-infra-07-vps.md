# AI基建的第七步：进阶到 VPS——没有一台长期在线的 Mac mini，也可以给 AI 准备一台“永不关机的电脑”

前面第六步讲的是远程工作环境。

我的理想状态其实很简单：在家里或者办公室放一台 Mac mini，长期插电、长期联网，上面跑 Agent、MCP、脚本和各种自动化任务。人在外面的时候，用手机远程看看进度。

但现实中，并不是每个人都有这样的条件。

比如办公室晚上会断电、公司网络有限制、没有地方长期放一台电脑、人在不同城市、不希望家里的电脑24小时开机，或者希望某些任务真正做到全天在线。

这时候就可以考虑进一步搭建一台：

**VPS。**

不过这一篇我先把结论放在前面：

**VPS不是AI基建的必需品。**

绝大多数普通 AI 用户都用不到。

如果一台 MacBook 或 Mac mini 已经能够满足需求，完全没必要为了“显得专业”再折腾服务器。

但如果确实需要一台长期联网、随时可访问、24小时运行的机器，VPS就是一个很有价值的补充。

## 一、先解释一下：VPS到底是什么？

VPS 全称是 Virtual Private Server，中文一般叫“虚拟专用服务器”。

其实可以把它简单理解成：

**你花钱租了一台放在别人机房里的电脑。**

它没有显示器，没有键盘，也不会摆在你的桌子上。

但它有 CPU、内存、硬盘、操作系统、公网 IP、网络连接。

而且通常：

**24小时开机、24小时联网。**

你通过 SSH 等方式远程连接进去，就可以像控制自己的电脑一样让它工作。

所以如果 Mac mini 是：

**放在自己家里的AI工作站。**

那么 VPS 就是：

**放在云端机房里的AI工作站。**

## 二、为什么Agent时代，VPS开始变得有价值

以前普通人很少需要服务器。

但到了 Agent 时代，很多普通用户开始有了一个新的需求：

**希望某些东西一直在线。**

比如 MCP Server、知识库检索服务、GitHub 自动同步、定时抓取公开资料、监控任务、数据库、API 中转、Webhook、自动化脚本、定期生成报告、各种 Agent 后台任务。

这些东西有一个共同特点：

电脑一关机，它们就停止。

如果全部放在自己的 MacBook 上，就意味着 MacBook 必须一直开着。

于是 VPS 就有价值了。

把需要长期运行的东西放到 VPS：

**自己的电脑关机，服务仍然继续。**

## 三、如果没有长期放Mac mini的环境，VPS尤其合适

Mac mini 有一个前提：

**你得有地方放它。**

而且那个地方最好不断电、网络稳定、不会有人随便关机、路由器稳定、你还能远程连接进去。

如果这些条件做不到，VPS反而简单。

因为服务器在专业数据中心里。

你不需要管家里停电、办公室断网、路由器重启、电脑被人拔掉电源、物业检修。

所以对于没有固定长期在线电脑的人，我觉得：

**与其为了跑几个后台服务专门买一台电脑，不如先租一台便宜的VPS试试。**

## 四、VPS最大的优势：24小时在线

假设我做了一个 IPO 问询案例知识库。

我希望每天凌晨自动检查交易所网站、发现新增项目、下载问询回复、整理文档、生成 Markdown、更新索引、提交 GitHub。

如果放在我的 MacBook 上，晚上电脑合盖以后，任务就可能停了。

如果放在 VPS 上，我睡觉的时候，它照样工作。

第二天早上打开 GitHub，资料已经更新好了。

这就是我理解的 Agent 时代服务器价值：

**把“需要一直有人开着电脑”这件事情取消掉。**

## 五、第二个优势：你在哪里都可以访问

VPS一般有公网地址。

只要有网络，就可以远程连接。

如果再配合 Tailscale 之类的工具，还可以把 Mac mini、MacBook、iPhone、VPS、其他电脑放进自己的虚拟局域网。

于是 VPS 就变成整个 AI 工作系统里的一个长期节点。

## 六、第三个优势：非常适合运行“服务型”的东西

这里要特别区分：

**电脑上的 Agent 工作**

和

**后台服务**

并不是完全一回事。

比如让我在一台机器上审查 Word、阅读几十份 PDF、处理客户材料、修改合同、查看结果、反复跟 Agent 对话，我个人还是更喜欢 Mac，因为有完整的图形界面。

但如果运行的是 MCP Server、数据库、网站、API、定时脚本、GitHub 自动任务、爬虫、知识库接口，VPS往往更合适。

所以我的一个简单划分是：

> **需要“人机交互”的工作，优先Mac。**
>
> **需要“长期后台运行”的工作，可以考虑VPS。**

## 七、VPS还有一个好处：便宜

如果只是跑轻量服务，其实没有必要买特别高配置。

很多 VPS 一个月的成本并不高。

相比为了运行几个后台服务专门买电脑、占地方、全年开机、还要考虑网络和电源，租一台 VPS 有时候反而更简单。

而且可以先买最低配置，发现不够再升级，不需要了就停掉。

## 八、但是VPS有一个很大的问题：它不是你的电脑

Mac mini 买回来以后，机器是你的。

但 VPS 是租的。

服务器实际上掌握在云服务商手里。

这就意味着：

**你对这台机器的控制权，并没有想象中那么绝对。**

比如可能遇到账号被冻结、付款失败、信用卡过期、忘记续费、云服务商清理实例、服务商发生故障、硬盘损坏、账号被封、误操作删除服务器。

如果服务器被删除，而又没有备份：

**里面的数据真的可能就没了。**

## 九、千万不要把重要资料“唯一一份”放在VPS上

这是这一篇我最想强调的地方之一。

假设你把一个知识库跑在 VPS 上，里面积累了一年数据。

然后有一天 VPS 到期了，你忘记续费，过了服务商的数据保留期，实例被删除。

这时候才突然发现：

**服务器里那份数据是唯一的一份。**

就非常麻烦。

所以我的原则是：

**VPS可以运行数据，但不要成为数据唯一的家。**

比如 Skill 同步 GitHub；知识库源文件同步 GitHub 或云盘；数据库定期导出；服务器配置做备份；重要目录自动同步；必要时做 VPS 快照。

真正成熟的服务器思维不是：

**“这台VPS永远不会坏。”**

而是：

**“这台VPS随时可以坏，但坏了我也能重新建一台。”**

## 十、VPS最容易被忽略的另一个问题：安全

VPS 长期连接互联网。

只要有公网 IP，就可能不断有人扫描端口、尝试登录、撞密码、寻找漏洞。

所以如果要使用 VPS，至少应该有一些最基础的安全意识。

比如 SSH 尽量使用密钥登录、关闭不必要的端口、系统及时更新、重要账号开启双因素验证、API Key 不要直接写进公开 GitHub、数据库不要随便暴露到公网、管理后台设置好密码、定期检查服务器有没有异常。

这些事情现在也不一定需要自己全部懂，完全可以让 Agent 帮忙检查。

比如直接告诉 AI：

> 检查这台服务器目前的安全配置，列出开放端口、SSH设置、系统更新、防火墙和异常登录情况，在不影响现有服务的情况下提出加固方案。

但最终还是要有一个意识：

**VPS不是买完以后就可以不管。**

## 十一、律师使用VPS，还要额外考虑客户数据

对律师来说，还有一个比普通用户更重要的问题：

**客户资料能不能放上去。**

如果 VPS 只是运行公开法律法规、公开案例、公开 IPO 问询资料、自己的 Skill、自动化脚本、公开知识库，问题相对简单。

但如果准备把客户合同、尽调底稿、身份证件、交易文件、未公开财务资料、诉讼证据、内幕信息直接上传到第三方 VPS，就必须更加谨慎。

至少需要考虑服务器位于哪里、服务商是谁、数据是否加密、账号权限、备份放在哪里、有没有日志、是否符合客户的保密要求、有没有数据跨境问题。

所以我的建议是：

**VPS首先用于运行“工具和公开数据”，敏感客户资料尽量留在受控的本地环境。**

## 十二、VPS还有一个缺点：学习成本比Mac高

Mac 买回来，打开界面就能用。

VPS 买回来，很多时候只有一个 IP 地址、用户名和密码或者 SSH Key。

然后你看到的是：

```bash
root@server:~#
```

你需要慢慢接触 SSH、Linux、端口、防火墙、Docker、域名、HTTPS、服务进程。

但现在 Agent 改变了这一点。

很多操作可以直接交给 AI：

> 在这台 Ubuntu VPS 上安装 Docker。
>
> 帮我部署这个 GitHub 项目。
>
> 配置 HTTPS。
>
> 检查为什么3000端口打不开。
>
> 把这个程序设置成服务器重启后自动启动。

所以 VPS 的技术门槛仍然存在，但已经比过去低很多了。

## 十三、VPS和Mac mini到底怎么选？

如果你经常需要图形界面，主要处理 Word、PDF 和本地文件，要做大量法律文书工作，希望 Agent 直接操作自己的资料，家里或办公室有稳定联网环境，我还是更推荐：

**Mac mini。**

如果你没有地方长期放电脑，需要24小时运行，主要跑MCP、网站、数据库和脚本，需要公网服务，需要定时任务，希望人在任何地方服务器都在线，就可以考虑：

**VPS。**

而如果用得比较深，最后往往不是二选一，而是：

**Mac + VPS。**

Mac负责工作。

VPS负责服务。

## 十四、我比较喜欢的架构其实是“本地工作，云端运行”

MacBook：日常移动办公。

Mac mini：处理本地资料、跑 Agent、保存重要工作文件。

VPS：运行 MCP、数据库、网站、API 和自动化服务。

GitHub：保存 Skill、代码、知识库和配置。

Tailscale：把所有设备连接起来。

手机：远程查看和管理。

这样每个东西负责自己最擅长的事情，而不是试图让一台机器解决所有问题。

## 十五、服务器真正应该“无状态化”

用 VPS 最值得建立的观念叫：

**服务器可以随时重装。**

今天这台 VPS 被删了，没关系。

重新创建一台新的，从 GitHub 拉代码，恢复配置，恢复数据库备份，重新启动服务，基本恢复。

所以以后我会越来越倾向于把程序放 GitHub、数据做备份、配置写成脚本、服务器只负责运行。

这样服务器本身反而没那么重要。

**重要的是服务器背后的数据和配置。**

## 十六、所以VPS是进阶选项，不是必修课

如果你现在只使用 ChatGPT，偶尔用一下 Codex，电脑也不需要长期运行，没有 MCP Server，没有自动化任务，也没有自己的知识库服务，那么：

**完全不用买。**

不要为了搭 AI 基建而搭 AI 基建。

但如果某一天你开始发现：“这个服务电脑关机以后就没了。”“这个脚本我希望每天自动运行。”“这个 MCP 我希望随时都能访问。”“我没有条件长期放一台 Mac mini。”

那就说明：

**你可能真的需要一台VPS了。**

所以我的 AI 基建第七步是一个进阶选项：

**如果需要一台24小时联网的机器，可以开始学习使用VPS。**

它的优势很明显：便宜、长期在线、随时访问、适合后台服务，特别适合 MCP、知识库、数据库和自动化。

但它的缺点同样明显：需要一定维护、存在安全风险、敏感数据需要谨慎、服务商可能出问题、忘记续费甚至可能导致数据丢失。

所以使用 VPS 最重要的一条原则，我觉得可以写在服务器旁边：

**服务器可以丢，数据不能丢。**

不要把真正重要的东西，只留在一台你租来的电脑里。
