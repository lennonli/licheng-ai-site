# AI基建的第七步：进阶到 VPS——没有一台长期在线的 Mac mini，也可以给 AI 准备一台“永不关机的电脑”

**VPS不是AI基建的必需品。** 绝大多数人一台 MacBook 或 Mac mini 够用，别为了“显得专业”去折腾服务器。但确实需要一台长期联网、随时可访问、24小时运行的机器，VPS 是很有价值的补充。

我理想的配置是家里或办公室放一台 Mac mini，长期插电联网，跑 Agent、MCP、脚本和自动化，人在外面手机看进度。但办公室晚上断电，公司网络受限，没地方放电脑，不想家里电脑24小时开着，或者有些任务就是要全天在线——这时可以考虑 **VPS**。

## 一、VPS是什么

VPS，Virtual Private Server，虚拟专用服务器：**你花钱租了一台放在别人机房里的电脑。**

没显示器，没键盘。但 CPU、内存、硬盘、操作系统、公网 IP 都有，通常 **24小时开机、24小时联网**。用 SSH 等方式连进去，像操作自己的电脑一样用。

Mac mini 是家里的 AI 工作站，VPS 是云端机房里的 AI 工作站。

## 二、为什么Agent时代VPS有价值

Agent 时代多了一个需求：**有些东西要一直在线。**

MCP Server、知识库检索服务、GitHub 自动同步、定时抓取公开资料、监控任务、数据库、API 中转、Webhook、自动化脚本、定期生成报告、各种 Agent 后台任务。

共同点：电脑一关，全停。放到 VPS 上，**自己的电脑关机，服务照样跑。**

## 三、没地方长期放Mac mini，VPS尤其合适

Mac mini 的前提是**你得有地方放它**，还得不断电、网络稳定、没人随手关机、能远程连进去。做不到，VPS 反而简单：服务器在专业数据中心，停电、断网、被人拔电源，都不用你管。

**与其为了跑几个后台服务专门买一台电脑，不如先租一台便宜的VPS试试。**

## 四、VPS的几个优势

**第一，24小时在线。**

比如我做 IPO 问询案例知识库，希望每天凌晨自动检查交易所网站、发现新增项目、下载问询回复、整理文档、生成 Markdown、更新索引、提交 GitHub。

放在 MacBook 上，晚上一合盖，任务可能就停了。放在 VPS 上，我睡觉它干活，第二天早上 GitHub 里资料已经更新好了。

**第二，在哪都能访问。**

VPS 一般有公网地址，有网就能连。再配合 Tailscale 之类的工具，把 Mac mini、MacBook、iPhone、VPS、其他电脑放进自己的虚拟局域网，VPS 就成了整个 AI 工作系统里的一个长期节点。

**第三，适合跑“服务型”的东西。**

审 Word、读几十份 PDF、处理客户材料、改合同、看结果、反复跟 Agent 对话，我还是更喜欢 Mac，有完整的图形界面。

跑 MCP Server、数据库、网站、API、定时脚本、GitHub 自动任务、爬虫、知识库接口，VPS 往往更合适。

> **需要“人机交互”的工作，优先Mac。**
>
> **需要“长期后台运行”的工作，可以考虑VPS。**

**第四，便宜。**

跑轻量服务不用高配，很多 VPS 一个月成本不高。先买最低配，不够再升，不用就停。

## 五、最大的问题：它不是你的电脑

Mac mini 买回来，机器是你的。VPS 是租的，实际掌握在云服务商手里，**你的控制权没有想象中那么绝对。**

账号被冻结、付款失败、信用卡过期、忘记续费、服务商清理实例、服务商故障、硬盘损坏、账号被封、误操作删了服务器，都可能遇到。

服务器被删，又没备份，**数据真的可能就没了。**

## 六、千万不要把重要资料“唯一一份”放在VPS上

知识库在 VPS 上跑了一年。某天忘了续费，过了服务商的数据保留期，实例被删。这时才发现：**服务器里那份数据是唯一的一份。**

**VPS可以运行数据，但不要成为数据唯一的家。**

Skill 同步 GitHub；知识库源文件同步 GitHub 或云盘；数据库定期导出；服务器配置做备份；重要目录自动同步；必要时做 VPS 快照。

成熟的服务器思维不是“这台VPS永远不会坏”，而是**“这台VPS随时可以坏，但坏了我也能重新建一台。”**

## 七、安全不能忽略

有公网 IP，就会不断有人扫端口、试登录、撞密码、找漏洞。**VPS不是买完以后就可以不管。**

最基础的几条：SSH 尽量用密钥登录；关掉不必要的端口；系统及时更新；重要账号开双因素验证；API Key 别直接写进公开 GitHub；数据库别随便暴露到公网；管理后台设好密码；定期检查服务器有没有异常。

不一定要自己全懂，可以让 Agent 查：

> 检查这台服务器目前的安全配置，列出开放端口、SSH设置、系统更新、防火墙和异常登录情况，在不影响现有服务的情况下提出加固方案。

## 八、律师还要额外考虑客户数据

律师比普通用户多一个问题：**客户资料能不能放上去。**

VPS 只跑公开法律法规、公开案例、公开 IPO 问询资料、自己的 Skill、自动化脚本、公开知识库，问题相对简单。

要把客户合同、尽调底稿、身份证件、交易文件、未公开财务资料、诉讼证据、内幕信息直接传到第三方 VPS，就得谨慎。至少要想清楚：服务器在哪、服务商是谁、数据是否加密、账号权限、备份放哪、有没有日志、是否符合客户的保密要求、有没有数据跨境问题。

**VPS首先用于运行“工具和公开数据”，敏感客户资料尽量留在受控的本地环境。**

## 九、学习成本比Mac高

Mac 买回来，打开就能用。VPS 买回来，往往只有一个 IP 地址、用户名和密码或者 SSH Key。然后你看到的是：

```bash
root@server:~#
```

SSH、Linux、端口、防火墙、Docker、域名、HTTPS、服务进程，都得慢慢接触。好在很多操作现在可以直接交给 AI：

> 在这台 Ubuntu VPS 上安装 Docker。
>
> 帮我部署这个 GitHub 项目。
>
> 配置 HTTPS。
>
> 检查为什么3000端口打不开。
>
> 把这个程序设置成服务器重启后自动启动。

门槛还在，但比过去低多了。

## 十、VPS和Mac mini怎么选

经常要用图形界面，主要处理 Word、PDF 和本地文件，法律文书工作量大，希望 Agent 直接操作自己的资料，家里或办公室联网稳定——我更推荐 **Mac mini**。

没地方长期放电脑，需要24小时运行，主要跑 MCP、网站、数据库和脚本，需要公网服务和定时任务，希望人在哪服务器都在线——可以考虑 **VPS**。

用得深了，往往不是二选一，而是 **Mac + VPS**：Mac 负责工作，VPS 负责服务。

## 十一、我喜欢的架构：本地工作，云端运行

- MacBook：日常移动办公。
- Mac mini：处理本地资料、跑 Agent、保存重要工作文件。
- VPS：运行 MCP、数据库、网站、API 和自动化服务。
- GitHub：保存 Skill、代码、知识库和配置。
- Tailscale：把所有设备连起来。
- 手机：远程查看和管理。

## 十二、服务器应该“无状态化”

**服务器可以随时重装。** 这台 VPS 被删了，新建一台，从 GitHub 拉代码，恢复配置，恢复数据库备份，重启服务，基本就回来了。

我的做法：程序放 GitHub，数据做备份，配置写成脚本，服务器只负责运行。

## 十三、VPS是进阶选项，不是必修课

如果你现在只用 ChatGPT，偶尔用用 Codex，电脑不需要长期运行，没有 MCP Server，没有自动化任务，也没有自己的知识库服务——**完全不用买。**

哪天你开始发现：“这个服务电脑一关就没了。”“这个脚本我想每天自动跑。”“这个 MCP 我想随时能访问。”“我没条件长期放一台 Mac mini。”——**你可能真的需要一台VPS了。**

用 VPS 最重要的一条原则，可以写在服务器旁边：**服务器可以丢，数据不能丢。**
