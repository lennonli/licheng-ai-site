# 如何写一个规范的临时对话提示词

对于已经配置好全局指令、Skill 和 MCP 的本地 Agent，临时对话提示词不需要很长。它的作用不是重复告诉 AI“你是谁、应遵守什么规则”，而是明确这一次具体任务的几个变量。

最实用的结构可以概括为：

**任务 + 输入 + 工作内容 + 输出 + 落地位置。**

例如（可直接套用，替换【】内的内容即可）：

```text
请处理【任务名称】。输入材料位于【文件/文件夹绝对路径】，重点查看【具体文件名】。请根据输入的资料完成【具体工作】工作，并输出【DOCX/Markdown/Excel/PDF等具体格式】，包括【修改版合同/法律分析/风险清单/修改说明等】。最终文件保存至【输出文件夹绝对路径】，不得覆盖原始文件；完成后列明生成文件名称及完整路径，并提示需要人工确认的事项。
```

这几个要素分别解决不同问题。

**“输入材料位于哪里”** 是为了让 Agent 明确从哪里读取资料，尤其是本地 Agent 最好直接写具体文件或绝对路径，避免误读其他版本或无关文件。

**“完成什么工作”** 用于限定任务边界。不要只写“处理一下”“看一下”，而应明确是合同审阅、证据整理、法律研究、案例检索还是文件比较。

**“输出什么”** 是为了明确交付标准。例如要求输出 DOCX 合同修改版、Excel 风险清单或者 Markdown 法律研究报告，不要让 Agent 自己判断最终成果形式。

**“保存到哪里”** 则是本地 Agent 特别重要的一项。Agent 不只是回答问题，还要把成果真正落地到项目目录。因此应明确输出文件夹，并要求不得覆盖原始文件。

最后增加 **“列明生成文件名称、完整路径和待人工确认事项”**，可以避免 Agent 只回复一句“已完成”，便于律师快速检查实际成果。

如果任务需要特定外部数据，再补充一句即可：

```text
如需核验【法律法规、案例、工商信息等】，请调用【MCP 名称】。
```

这里同样不需要重复详细规则。如果全局指令已经规定法律依据必须核验、合同修改采用最小必要修改、不得编造案例等要求，就不必每次重新写。

因此，一个成熟的本地 Agent 使用方式应当是：

> **全局指令负责长期规则，Skill 负责标准流程，MCP 负责外部数据，临时提示词只负责说明这次具体做什么。**

临时提示词越接近真实的“工作指令”，而不是一篇复杂的“提示词作文”，日常使用效率通常越高。
