# AI基建的第五步：注册一个 GitHub 账号，并真正把它用起来

第五步：注册一个 GitHub 账号，然后真正用起来。

别被名字吓住。我以前也以为它是程序员写代码的地方。现在我的看法是：

**GitHub 很可能是 AI 时代每个重度用户都该掌握的基础工具。**

只要开始用 Agent、Skill、MCP、知识库，它很快就会出现。

## 一、GitHub 是什么

不讲技术：**一个专门保存、管理、同步“项目文件”的云端仓库。**

程序员写软件，几百个文件，天天改，几个人一起改。总不能这样命名：

`最终版.docx`

`最终版2.docx`

`最终版真的最终版.docx`

所以有了 Git。谁改了什么、什么时候改的、改前改后什么样，它都记着，需要时能退回旧版本。GitHub 就是把 Git 仓库放到网上。

粗略理解：**带完整版本管理的云端项目文件夹。**

## 二、为什么它不再只是程序员的东西

以前看到一个 GitHub 项目，满屏代码、README、配置文件，律师大概率直接关掉。

现在把地址丢给 Agent：

> 看一下这个项目是干什么的，适不适合我使用。如果适合，帮我下载安装到电脑上并完成配置。

后面很多事，AI 自己能办完。

**不用当程序员，也能用上程序员造的工具。**

再进一步，不写代码，也能让 AI 建项目、改代码、提交版本、修 Bug、写脚本、部署服务。

## 三、第一个用途：管理 Skill

Agent 用久了，你不会每次重新教它怎么审合同、整理证据、写法律意见书、查 IPO 问询回复、处理 Excel、做 Word、检索案例。成熟的方法，应该沉淀成 Skill：

`contract-review`

`legal-research`

`ipo-inquiry-review`

`litigation-evidence`

`word-formatting`

Skill 大多就是：**文字规则 + 配置文件 + 脚本 + 模板。** 正是 GitHub 最擅长管的东西。

我在 Mac mini 上改了一个 Skill，提交到 GitHub，MacBook 同步一次，两台就一致。换电脑，把仓库拉下来就行。

GitHub 就是**自己的 Skill 中央仓库**。

## 四、第二个用途：建自己的知识库

这一点对律师最有价值。

法规、案例、IPO 问询、审核案例、监管规则、项目总结、行业资料，以前都扔进文件夹。换个思路：

```text
法律知识库
├── 公司法
├── 劳动法
├── 合同法
├── 争议解决
├── IPO审核
├── 上市公司监管
└── 新三板
```

内容整理成 Markdown、JSON 等结构化文件。好处是：**特别适合 AI 读。**

Agent 直接连上这个知识库：

> 查找知识库里所有涉及“劳务派遣超过10%”的 IPO 案例。

> 总结2026年以来北交所审核中关于关联交易规范性的主要关注点。

这时 GitHub 就是**AI 能直接读取的专业知识仓库**。

而且它得不断长。项目结束，把脱敏后的核心分析放进去；看到好案例，加进去；规则更新，换掉旧版；分类不合理，让 Agent 调目录。

每一次变化 GitHub 都记着。知识库不再是静态文件夹，而是**不断迭代的专业资产**。

## 五、多台电脑同步

Mac mini、MacBook、VPS、办公室电脑、家里电脑，**怎么让所有设备上的 Agent 用同一套东西？**

最简单的办法之一就是 GitHub。都从同一个仓库取，有更新就同步，改完再提交。

不会再出现这台 Skill 是新版、那台还是三个月前的、Mac mini 又单独改过一个。

## 六、AI 的“基础设施配置”也放进去

Agent 全局指令、Skill、Prompt 模板、MCP 配置、自动化脚本、Docker 配置、服务器部署脚本、知识库处理程序、数据清洗脚本、OCR 工具、文档转换工具，都适合放 GitHub。

整套 AI 工作系统，最后就是一个仓库。

换电脑时，不用再想“我以前到底装过什么”，直接交给 Agent：

> 按照这个仓库，把我的 AI 工作环境重新部署出来。

## 七、很多 AI 工具首发在 GitHub

新的 Agent、MCP、Skill、开源模型、知识库工具、自动化项目、OCR、文档处理工具，常常先出现在 GitHub，不是 App Store。

会不会用 GitHub，影响你能不能及时用上这些东西。

以前看到 GitHub 地址，我觉得跟我没关系。现在第一反应是：

> 把这个项目给 Agent 看一下，看能不能为我所用。

## 八、让 GitHub 自动干活

GitHub Actions，简单说：**某件事发生后，让 GitHub 自动执行一段任务。**

每天抓新资料、更新知识库、整理数据、生成索引、检查文件、部署网站、更新 MCP 服务。电脑不用开着，直接在 GitHub 上跑。

它不只是仓库，还是**免费的自动化基础设施平台**。

## 九、律师必须注意：保密

**别图方便，把客户资料扔进公开仓库。**

客户合同、尽调材料、身份证件、内部法律意见、诉讼材料、未公开交易信息、上市公司内幕信息，以及其他有保密义务的资料，都不行。

GitHub 分 Public Repository 和 Private Repository，用之前先搞清楚仓库权限。

API Key、密码、Token、服务器密钥、数据库密码，也别写进仓库。

我的原则：**GitHub 管“可复用的方法和知识”，客户原始材料单独管。**

## 十、它不是另一个网盘

几百个 PDF、几十 GB 视频、大量扫描件、原始底稿，放 Google Drive、OneDrive、iCloud 这类网盘更合适。

Markdown、代码、配置、脚本、Skill、Prompt、结构化知识、项目说明、版本不断变化的文本，放 GitHub。

**网盘擅长存文件。GitHub 擅长管不断迭代的项目。**

AI 工作系统，恰好越来越像一个长期迭代的软件项目。

## 十一、个人 AI 系统的“中央仓库”

大模型负责思考，Agent 负责执行，电脑提供运行环境，MCP 连接外部数据。GitHub 负责：**保存和同步你自己的 AI 能力。**

Skill、知识库、脚本、MCP 配置、项目、更新历史，都在这里。换模型、换 Agent、换电脑，都不怕。

## 十二、第五步不是学编程，先注册账号

不用先学 Git，不用学命令行，更不用学编程。

**先注册一个 GitHub 账号**，然后慢慢用：

- 第一阶段：收藏别人做好的项目；
- 第二阶段：让 Agent 帮你安装 GitHub 项目；
- 第三阶段：把自己的 Skill 放进去；
- 第四阶段：建自己的知识库；
- 再往后：让 Agent 管仓库、提交代码、自动同步、跑 GitHub Actions。

所以我的 AI 基建第五步是：**注册一个 GitHub 账号，把它当成自己 AI 工作系统的一部分。**

GitHub 以前是程序员的主场。到了 Agent 时代，它正在变成更通用的基础设施。

**模型是租来的。Agent 也可能会换。真正值得长期积累的，是属于自己的 Skill、知识和工作系统。**

GitHub，是目前很适合放这些东西的地方。
