# 举报专项核查意见通用教程（发行人律师）

适用场景：交易所因举报向发行人下发《专项核查通知》，要求保荐机构、发行人律师核查并发表明确意见。本教程写给执行这项工作的 AI，也可以给人看。按阶段使用，不必一次读完。

文中【 】为占位，换成本案内容。

---

## 一、固定要求（每一轮都适用）

1. **署名**：Word 修订人、批注回复人、文档最后修改人统一用用户指定的署名（例如“ABL-李成”）。
2. **修订时间**：用用户所在时区（例如台北时间 UTC+8），落在“收到文件之后、完成修订之前”。按批注或章节分批修改，各批时间自然不同。不回填、不伪造、不批量改写修订时间。
3. **Word 时间格式**：Word 把作者的本地时间写成带 Z 的形式（`2026-01-01T17:05:12Z` 在 Word 里显示为 17:05）。用程序写修订时，`w:date` 要写本地时间的数字。写成 UTC 数字，Word 里显示的时间会早几个小时，甚至早于对方的批注。
4. **两份交付**：每一轮都出“修订模式”和“清洁版”。清洁版等于修订模式版接受全部修订后的结果，两者逐段一致。
5. **以用户最新版本为底**：在用户发来的那一版上叠加修订，保留其已有的修订和批注，不用自己手上的旧版覆盖用户改动。版本号顺延（用户发 v4，就出 v5）。
6. **批注逐条回复**：对方每条批注下都回复改法；不改的写明理由。
7. **正文干净**：待核实事项、风险提示、需要拍板的问题写在给用户的回复里，不写进正文。正文不出现【请补充】【请确认】一类提示语。无法确定的数字留【 】，不编造。
8. **事实可溯源**：正文每个事实都能对应到某个底稿编号。答不出“这个信息在哪个底稿”的事实，要么补底稿，要么删。
9. **只用指定材料**：用户说“只按 X 做”，就不混入其他来源。
10. **默认不补充披露**：除非用户决定补充披露，全文不出现“补充披露”“一并披露”等字样。论证方向是“该事项不属于应披露的信息”。

## 二、流程总览

| 阶段 | 用户通常怎么说 | 产出 |
|---|---|---|
| 0 接案 | 发来通知、举报附件、上一份核查意见做模板 | 材料登记、问题拆解表、材料缺口清单 |
| 1 初稿 | “起草专项核查意见” | 律师稿初稿（清洁版）、需拍板事项、待补材料 |
| 2 用户批注轮 | “这是我的修改，有批注” | 律师稿下一版（修订模式＋清洁版） |
| 3 底稿 | “按核查程序做底稿，打包，缺的列清单” | 底稿包、底稿索引及待补清单、访谈笔录、公开检索记录 |
| 4 内核文件 | “做内核文件” | 查验计划、底稿目录、律师工作情况的说明、内核会议纪要（清洁版） |
| 5 券商稿 | “按券商批注修改，然后同步律师稿” | 券商稿（修订＋清洁）、律师稿下一版、受影响的内核文件 |
| 6 新事实 | “收到裁决书（或函件），据此更新” | 券商稿、律师稿、内核文件、访谈笔录、底稿同步更新 |
| 7 内核批注轮 | “这是券商内核的批注” | 同阶段 5，另列与已定口径冲突的批注 |
| 8 交付 | — | 命名、自检、回复用户 |

## 三、阶段 0：接案

1. **读通知原文**，记下：标题、问题数、每问的“请发行人说明（1）（2）（3）”、要求谁发表意见、回复期限（通常 10 个工作日）、签字盖章要求。
2. **读举报附件**：协议、仲裁或诉讼材料、函件。扫描件逐页看，引用原文前回到原件核对条款号和原话。
3. **读申报文件**：招股说明书（以最新稿为准）、法律意见书及补充法律意见书、历轮问询回复。先检查哪些 PDF 损坏、打不开，找替代来源。
4. **读用户给的模板**：上一份专项核查意见（版式、声明、签署页）、访谈笔录模板。
5. **登记材料**：每份材料记下文件名、格式、页数、要点、异常，后面各阶段直接查。
6. **拆题**（见第十一节 B0），列出需要用户拍板的问题和需要补充的材料。

常见材料清单：

| 类别 | 材料 | 用途 |
|---|---|---|
| 举报本身 | 通知、举报附件（协议、仲裁申请书、证据清单、受理通知、函件） | 拆题、引原文 |
| 主体信息 | 各相关主体的工商登记资料、企业信用报告 | 股权结构、人员、注册资本变更、诉讼保全 |
| 财务 | 相关主体的财务报表、银行开户清单、银行流水 | 是否开展业务、资金往来、财产是否混同 |
| 履约 | 项目备案表、土地出让合同、主管部门函件 | 协议执行情况 |
| 争议 | 仲裁或诉讼材料、裁决书或判决书 | 争议进展和结果 |
| 实控人 | 个人征信报告、承诺函、所控制其他企业的财务报表、证券登记机构出具的持有人名册及质押冻结信息 | 履约能力、股份权利限制 |
| 发行人 | 专利证书、核心技术资料、员工花名册 | 技术、人员是否流向争议项目 |
| 访谈 | 实控人访谈笔录（按模板起草，待签字） | 背景、原因、主观说明 |
| 公开检索 | 审判流程信息公开网、执行信息公开网、人民法院公告网、信用中国等 | 涉诉、被执行、失信 |

常见问题：

- 申报文件内部数字不一致（同一公司注册资本两处写法不同、关联方标注不一致）：正文用【 】标出，回复里提醒用户。这类笔误更正不等于补充披露。
- 举报附件本身有异常（例如证据清单的提交人与申请人对不上）：提醒用户核实，不在正文里下结论。
- 公开检索网站打不开：如实写明，不写成已查询；可用商业数据库替代检索公司（多数不能查自然人），官网截图请用户在本地补查。

## 四、阶段 1–2：律师专项核查意见

### 4.1 全文结构

以用户提供的上一份专项核查意见为版式（字体、段落、表格样式、签署页）。上一份签署页的盖章签字扫描图删掉，只留文字签署栏，日期写“【 】年【 】月【 】日”。

```
关于【发行人全称】
【申请文件名称，例：公开发行股票并在北交所上市申请文件】的
专项核查意见

致：【交易所】
【律所】（以下简称“本所”）受【发行人全称】（以下简称“发行人”或“公司”）委托，担任发行人【发行上市事项】的特聘专项法律顾问。根据【适用规则】的要求，本所律师对贵所出具的《关于【发行人全称】……的专项核查通知》（以下简称“《专项核查通知》”）所涉举报事项进行了核查，并出具本专项核查意见。
为出具本核查意见，本所及承办律师作如下声明：
1、【照模板】  2、【照模板】  3、【照模板】
4、为便于表述，本核查意见中下列简称具有如下含义：【释义表：简称 | 含义】
本所律师根据有关法律、法规，在充分核查验证的基础上，现出具本核查意见如下：

1.【通知中的问题标题，原文】
举报材料显示：【原文照录】
请发行人：【（1）（2）（3）原文照录】
请保荐机构、发行人律师核查上述事项并发表明确意见。
回复：
第一部分：发行人说明
一、【第（1）问原文】
（一）……
二、【第（2）问原文】
三、【第（3）问原文】
第二部分：核查程序与核查意见
一、核查程序
针对上述事项，本所律师履行了如下核查程序：
（1）取得并查阅……，核查……；
……
（N）通过……等公开渠道，检索……的涉诉、涉仲裁、被执行及失信情况。
二、核查意见
经核查，本所律师认为：
1、关于【第（1）问主题】的核查
2、关于【第（2）问主题】的核查
3、关于【第（3）问主题】的核查
（以下无正文）
（本页无正文，为《关于【发行人全称】……的专项核查意见》之签署页）
【律所】  负责人：【 】  经办律师：【 】【 】【 】
【 】年【 】月【 】日
```

### 4.2 释义表

- 收录正文所有简称：协议、项目、各签约方、相关公司、争议案件（含案号）、函件（含出具日期和全称）、规则、报告期。
- 协议各方的“甲乙丙丁方”只在释义和签约主体表里保留，分析部分一律用公司简称。
- **简称不能让人混淆**：两家公司名称相近时，主动选能区分业务的简称（例如“××零部件”“××实业”），不要都叫“××”。
- 持股比例全文两位小数（100.00%、35.00%）。

### 4.3 第一部分的写法

**通用顺序：背景 → 时间线 → 主体关系 → 逐问分析。**

1. **背景段**：协议是什么性质（例如招商引资协议，核心目的是项目落户、纳税、入统）；签约时各方股权结构、谁控制谁；后来发生的事件（退出、付款违约、仲裁、主管部门催告、对方函件、裁决），各写一句。协议的背景和事件的背景都要写。
2. **时间线表**（时间 | 事项）：只放与举报有关的事件，按日期排序。与举报无关的事件（例如辅导备案、发行人搬迁）不写。
3. **签约主体及与实控人关系表**（签约主体 | 协议地位 | 股权结构及主要人员 | 与实控人的关系）：签约时和现在的股权结构都写，写清谁是实际控制人。
4. **并列的几点说明加小标题**，例如“4、发行人、实际控制人与《××协议》签约主体的关系”。
5. 新主体、新事件第一次出现时，交代它和前面主体的关系、当时的股权结构；争议案件写明名称和案号。

**常见论证模块（按举报内容挑用）：**

| 审核关切 | 论证要点 | 常用依据 |
|---|---|---|
| 某企业是否实控人控制、是否已披露 | 股权链条＋任职；列出招股书披露位置表（披露位置 | 披露内容） | 招股书相关章节 |
| 关联方是否完整 | 逐家对照关联法人定义；参股、监事任职不构成控制 | 上市规则关联方条款、《企业会计准则第36号》 |
| 同业竞争 | 经营数据表（收入、净利润、总资产、员工）；要素对照表（历史沿革、资产、人员、主营业务、技术商标商号、客户供应商、替代性竞争性利益冲突） | 交易所关于同业竞争的适用指引 |
| 协议约束谁 | 合同相对性；法定代表人签字是职务行为；发行人不是当事人 | 《民法典》第四百六十五条、第六十一条 |
| 违约责任会不会传到实控人 | 有限责任；出资已缴足；人格否认需要事实，用财务报表、资金往来频率、负债情况支撑，结论措辞审慎（“未发现”） | 《公司法》第三条、第四条、第二十三条 |
| 是否影响控制权稳定 | 持股及一致行动安排；股份无质押冻结争议；潜在责任有限且由企业承担；实控人履约能力（所控制其他企业的经营规模、征信、可回收债权）；承诺函 | 证券登记机构信息、征信报告、承诺函 |
| 是否影响经营稳定 | 发行人不负担协议义务；资产、人员、财务、机构、业务独立；实控人能勤勉履职；业绩稳定 | 上市规则相关条款 |
| 举报是否属实 | 逐句拆分表（举报内容 | 核查情况 | 核查结论） | — |
| 未披露是否合规 | 逐条对照招股书准则表（准则条款 | 规定要求 | 披露情况及分析），再分“不存在虚假记载或误导性陈述”“不构成重大遗漏”逐点小结 | 招股说明书内容与格式准则 |

**协议内容与执行情况：**

- **协议条款表**（条款 | 主要内容）：只摘录协议原文，不夹分析。
- **义务履行表**（主要义务 | 义务主体 | 履行情况）：把协议所有义务条款逐条列出，不能漏条。每项写明“已履行／未履行／未按期履行／履行期限未届满／无法掌握及原因”。义务主体不同的分行列。
- **违约责任表**（违约情形 | 责任主体 | 违约后果 | 对应条款）：条款子项写全。表里只放协议内容，分析写在表下。
- **潜在责任测算表**（潜在责任项目 | 责任主体 | 测算依据 | 金额）：没有获得奖励就写“0元，××未获取任何扶持奖励”；对方尚未主张的写明“尚未主张”，不写“金额较小”。

**“举报事项是否属实”表：**

- 把举报原话逐句拆开，每句一行。
- 结论分层表述，例如：“存在××的情况属实；××个人作为协议当事人的表述不准确”“条款内容属实，但对条款性质及约束范围的理解有误”“属实，且已如实披露”“××属实，但履约义务主体是××而非××”“申请上市属实，但与协议履行不存在因果关系，举报将二者关联的表述不属实”。
- 某句本身是事实的，不能笼统认定“不属实”。先承认属实的部分，再说明为什么不构成违规。

**信息披露合规性：**

- 题目问什么就覆盖什么范围。问的是“举报事项未披露是否符合准则”，就要覆盖全部举报事项，不能只论证其中一份协议。
- 先归纳“举报所涉事项包括（1）……（4）……，其中第（1）项已披露，第（2）至（4）项未单独披露”，再逐条对照准则，最后分“不存在虚假记载或误导性陈述”“不构成重大遗漏”逐点小结。

### 4.4 第二部分的写法

**核查程序：**

- 每项格式：“取得并查阅【文件名】，核查【目的】；”或“访谈【对象】，了解【事项】；”或“通过【网站】等公开渠道，检索【主体】的【事项】。”
- **序号就是底稿编号**：程序（1）对应底稿 1-1，程序（N）对应 1-N。改程序就要同步底稿目录、查验计划、律师工作情况的说明和底稿包。
- 程序里写到的文件，底稿里必须有；正文用到的事实（例如承诺函、企业信用报告里的信息），程序里必须有对应的取得动作。
- 只写真正做了或一定会做的程序。网站没查到就不写成已查。

**核查意见：**

- “经核查，本所律师认为：”后分 1、2、3，与第一部分各问一一对应，标题用“关于××的核查”。
- 每点先给结论句，再用两三句话串起关键理由，最后一句回到问题本身。

### 4.5 文风

- 少用“需要说明的是”；代词“二者”“该公司”换成具体主体。
- 引用协议、规则原文要写全，不截半句。
- 每句为本段论点服务，与本段无关的结论句删去。
- 数据用最新期间，与报告期一致；做不到的写明原因。
- 数据与论点矛盾时（例如用来证明履约能力的企业净资产为负），不自行取舍，在回复里提示并给出写法选项，由用户决定。

## 五、阶段 3：核查程序与底稿

### 5.1 编号

- 底稿编号＝核查程序序号：程序（1）至（N）对应底稿 1-1 至 1-N，卷宗号与编号相同。
- 单份文件编号 1-x-y（例如 1-2-3）。扫描合订本按单份文件拆开（协议、回单、函件各成一份）。
- 同一份文件被两项程序用到（例如访谈笔录同时支撑两项程序），两处各放一份，底稿目录备注“同 1-x”。
- 0 文件夹放通知、核查意见、内核文件：0-1 通知、0-2 核查意见、0-3 律师工作情况的说明、0-4 内核会议纪要、0-5 底稿目录、0-6 查验计划。

### 5.2 底稿包结构

```
【发行人简称】专项核查底稿（【事项简称】）/
├── 0 底稿索引及待补清单.xlsx
├── 0 专项核查通知、核查意见及内核文件/
├── 1-1 《××协议》及附表/
│   └── 1-1 《××协议》及附表（YYYY.MM.DD）.pdf
├── 1-2 工商登记资料/
│   ├── 1-2-1 【主体】-企业信用报告（YYYY.MM.DD）.pdf
│   └── ...
└── 1-N 公开渠道检索记录/
```

文件名格式：`编号 主体-文件名称（日期）.扩展名`，日期写文件本身的日期（签署日、出具日、报告生成日）。

### 5.3 底稿索引及待补清单（xlsx，项目组内部用）

- 工作表“底稿目录”：底稿编号 | 底稿名称 | 原件/复印件 | 压缩包内文件 | 状态（已取得／部分待补：××／已起草待签字）。
- 工作表“待补底稿清单”：序号 | 核查程序 | 待补底稿 | 说明（正文哪句话依赖它） | 建议提供方。
- 给内核的底稿目录按定稿状态出（见第七节），两张表不要混。

### 5.4 事实与底稿对照表

起草和修改时维护一张表：正文事实 | 出处文件 | 页码或栏目 | 底稿编号。用户问“这个信息在哪个底稿”时直接查表。发现正文用到的信息不在底稿里，要么补底稿并在程序里加取得动作，要么删掉这句。

### 5.5 公开渠道检索

- 渠道：中国审判流程信息公开网、中国执行信息公开网、人民法院公告网、信用中国等。
- 做成 PDF：一份汇总表＋每个主体一份。汇总表写明检索时间、渠道、结果，以及未能检索的部分和补查方法。
- 没查到的渠道如实写，不写成已查询。

### 5.6 网络核查笔录

用户提供网核系统导出的信息表时，只按信息表制作笔录，不混入其他来源。结构照用户模板：

1. 标题：【发行人】相关主体涉诉、涉仲裁、被执行及失信情况查询笔录
2. 网络查询概况：查询时间、查询人员（签字）、查询内容、查询载体、查询期间（报告期初至查询日）
3. 核查对象表：序号 | 主体名称 | 与发行人的关系 | 统一社会信用代码／身份证号码 | 备注
4. 查询网址表：序号 | 网站名称 | 网址
5. 查询结论：公司、个人分别写；信息表显示“有相关记录”的，结论留【 】待用户核对（例如是否同名），不要自行认定
6. “查询截图见附件”

信息表里没有的内容用【 】标出，回复里说明。

## 六、阶段 5–7：券商稿、新事实、内核批注

### 6.1 券商稿与律师稿的差异

| 项目 | 律师稿 | 券商稿 |
|---|---|---|
| 开头 | “致：【交易所】”＋委托段＋声明＋释义 | 以券商模板为准，通常直接从释义开始 |
| 核查程序主语 | 本所律师履行了如下核查程序 | 保荐机构履行了如下核查程序 |
| 核查意见 | 经核查，本所律师认为： | 经核查，保荐机构认为： |
| 签署页 | 律所负责人、经办律师 | 发行人签章页＋保荐机构签章页 |
| “举报”字样 | 以律所模板为准 | 有的券商会全文改为“材料显示”“所称”“相关事项” |

券商稿去掉了“举报”字样而律师稿仍保留时，在回复里问用户律师稿要不要同步。

### 6.2 收到券商稿的处理步骤

1. 读全文、批注（含锚定原文）和修订。分清三类改动：券商批注（要按批注改）；券商留痕的修订（律师稿要同步）；券商未留痕的改动（与上一版律师稿逐段比对才找得出来，也要同步）。
2. 用户本人在券商稿上做的修订，同样同步到律师稿。
3. 在券商稿上修订，每条批注下回复；再把同样的改动做到律师稿上，律师稿版本号顺延。
4. 与已定口径冲突的批注：先不改或按默认改，回复里列出请用户定。
5. 核查程序变了：查验计划、底稿目录、律师工作情况的说明、底稿包同步改。
6. 两份稿的结论段、数字、日期最后逐段比对一次。用户只在其中一份里删过的内容，不要自作主张同步，在回复里说一声。

### 6.3 新事实进来时（裁决书、催告函等）

- 以用户这次指定的版本为底。
- 通常要改：释义（新增文件简称）、背景段、时间线、争议进展段（删去“尚在审理中”）、准则中重大诉讼仲裁一条、“不构成重大遗漏”一段、核查程序（取得××文件）、核查意见、查验计划和底稿目录对应行、访谈笔录里的进展一问、底稿包（新文件放进对应编号）。
- 裁决结果以原文为准：写裁决主文（金额、违约金计算标准、费用承担、连带责任、终局性和生效时间）。
- 先判断新事实是否改变结论口径（赔偿责任、举报是否属实）。会改变的，先把改法列给用户确认。
- 写“××年×月×日作出”，以文书落款日期为准，不写收到日期。

### 6.4 处理一轮批注的步骤

1. **确认底稿版本**：用用户这次发的文件。用户说“版本发错了”就整轮重做，旧输出作废并说明。文件里找不到用户说的批注时，直接告诉用户，请其重发。
2. **读全**：修订和批注都看，点批注（没有范围）结合前后文理解。
3. **列批注处理表**：批注人 | 锚定原文 | 意见 | 改法 | 是否与已定口径冲突 | 回复文字。
4. **改**：在用户版本上叠加修订，每条批注下回复。回复格式：“已按批注……”“已补充……，见第×部分”“经核对……，保留原表述，理由是……”。
5. **顺带修改**：批注之外顺手改的（编号、引用、因删减而失去依据的句子），回复用户时单独列出。
6. **同步**：律师稿、券商稿、内核文件、访谈笔录、承诺函、底稿包。
7. **回复用户**：交付说明 → 冲突与需拍板 → 注意事项。

### 6.5 冲突处理

- 后来的、层级更高的意见（券商内核＞券商项目组＞早期用户批注）一般优先；凡是推翻用户已定口径的，都在回复里列出，写明默认怎么处理的。
- 补齐内核要求的内容后，可能把用户之前删掉的风险又带回正文（例如补齐义务表后出现某项违约风险）。单独提醒，由用户决定删不删。

### 6.6 内核和券商常见批注（起草时就主动避免）

| # | 常见批注 | 起草时怎么做 |
|---|---|---|
| 1 | “这里突然出现了××，补充写一下与上面签约公司之间的关系” | 新主体第一次出现就交代关系 |
| 2 | “补充写一下当时的股权结构” | 涉及历史时点的，写当时的股权结构和比例 |
| 3 | “都保留两位小数” | 比例全文两位小数 |
| 4 | “写清楚主体” | 不用“二者”“该公司”这类代词 |
| 5 | “补充写一下这个公司的实际控制人” | 第三方公司写实际控制人，注明来源 |
| 6 | “报告期是三年一期，请补齐” | 数据期间与报告期一致，做不到的说明原因 |
| 7 | “就本段内容而言，为何要说这句？” | 删去与本段论点无关的结论 |
| 8 | “未见列××条的义务，请核对并补齐” | 义务表、违约表逐条对照协议，不漏条、不漏子项 |
| 9 | “没写是否履行了协议约定的义务” | 每项义务写明履行状态 |
| 10 | “主体不同，建议分开列” | 不同义务主体分行 |
| 11 | “突然出现了仲裁，建议直接写具体的仲裁案件名称” | 新概念第一次出现写全称、案号 |
| 12 | “表格主要是摘录协议内容，非协议内容建议不在表格中体现” | 摘录表只放原文，分析放表下 |
| 13 | “往来是否频繁？财产不混同的结论是否谨慎？” | 人格否认类结论配事实，措辞用“未发现” |
| 14 | “其现有资金实力如何？” | 履约能力写现有可用资金来源 |
| 15 | “请提供此承诺文件” | 正文提到的文件，底稿里要有 |
| 16 | “这句话本身是属实的吧，这个认定再考虑一下” | 属实认定逐句拆分，承认属实部分 |
| 17 | “没写全？” | 引用原文写全 |
| 18 | “先简要介绍事情背景，再说时间线” | 背景在前，时间线在后 |
| 19 | “这几个内容写在这里有点突兀，加一个小标题” | 并列说明加小标题 |
| 20 | “这一段不用写太详细，直接按现状写” | 与结论无关的细节压缩成现状描述 |

## 七、阶段 4：律所内核文件

律所出具专项核查意见前要过内核，通常四份文件：查验计划、底稿目录、律师工作情况的说明、内核会议纪要。有上一份内核文件时，以它的版式为准，只替换内容。

### 7.1 共同规则

- 清洁版。
- **按定稿状态出**：底稿目录全部按已取得列示，不写缺失提示（缺失清单另给项目组）。
- **只设一段**：查验计划和底稿目录不按通知的小问分节，统一一段，标题用通知的问题标题（例：“一、信息披露准确性的举报事项”）。
- **底稿就是核查程序**：核查意见有 N 项程序，查验计划和底稿目录就有 N 行，1-1 至 1-N 对应程序（1）至（N），卷宗号与序号相同。
- **查验计划写一个整体结论**，放在第一行的合并单元格里。
- **签字图片**：上一份文件签署页里的手签图片，签字律师相同就保留；人变了，提醒用户换图，不要自己删。
- **日期由用户给**：受理日、通知日、查验起止日、签署日、内核会议日。没给就按默认填（查验时间默认通知日至出具日，说明落款日默认内核会议日），回复里请用户确认。
- **内核委员每次抽签**：用户没给就沿用上一份的，并在回复里提醒用户换人要改。
- 抬头律所名称与核查意见落款一致。

### 8.1 文件命名

| 文件 | 命名 |
|---|---|
| 律师稿 | `【律所简称】关于【发行人简称】专项核查意见（【事项简称】）-【署名】-YYYYMMDD-vN.docx`，修订模式加“（修订模式）” |
| 券商稿 | `【券商简称】关于【发行人简称】专项核查意见-MMDD-【署名】[-事项].docx` |
| 内核文件 | `专项核查意见查验计划（【事项简称】）-【署名】-YYYYMMDD.docx`、`专项核查意见底稿目录（…）-【署名】-YYYYMMDD.docx`、`律师工作情况的说明（…）.docx`、`【发行人简称】内核会议纪要-专项核查意见（…）.docx` |
| 访谈笔录 | `【编号】【姓名】访谈笔录（待签字）[-更新事项].docx` |
| 承诺函 | `【姓名】承诺函（待签字）.docx` |
| 底稿包 | `【发行人简称】专项核查底稿（【事项简称】）.zip` |

- 版本号顺延用户最后一版：初稿 → 第二稿 → 第三稿 → 用户 v4 → v5……
- 日期用当天日期，不沿用旧文件名里的日期。
- 不要用新内容覆盖旧版本的文件名，否则后面分不清版本。

### 8.2 回复用户的写法

1. 先说交付了什么、在哪一版上改的、修订人是谁。
2. 再列需要用户拍板的点：与已定口径冲突的批注、事实缺口、二选一的写法，给出默认处理和理由。
3. 最后是注意事项：风险、底稿缺口、前后文件不一致（例如承诺函与核查意见、访谈笔录与核查意见）。
4. 不复述过程。用户只要某几处文字时，只发文字，不发整份文档。

### 8.3 交付前自检

- [ ] 修订人、批注回复人、最后修改人都是用户指定的署名；修订时间为用户所在时区，在收到文件之后
- [ ] 清洁版与修订模式版接受全部修订后逐段一致
- [ ] 对方每条批注都有回复；与已定口径冲突的已在回复里列出
- [ ] 律师稿、券商稿、查验计划、底稿目录、律师工作情况的说明、访谈笔录、承诺函、底稿包之间的核查程序、主体、数字、日期一致
- [ ] 核查程序序号与底稿编号一一对应；正文每个事实都能指到底稿
- [ ] 无“补充披露”等禁用词，无残留【请…】提示；剩余【 】是有意保留的
- [ ] 持股比例两位小数；数据期间与报告期一致
- [ ] 看过版式：表格、签署页、签字图片、页码

## 九、默认口径（用户另有指示的除外）

| 口径 | 说明 |
|---|---|
| 不补充披露 | 全文不出现“补充披露”“一并披露”，论证该事项不属于应披露信息 |
| 简称可区分 | 名称相近的公司用能区分的简称；分析部分不用甲乙丙丁方 |
| 时间线只写相关事件 | 与举报无关的事件不进时间线 |
| 题目问什么就覆盖什么 | 合规性论证覆盖全部举报事项 |
| 责任边界 | 加强“以出资额为限、不涉及实控人个人责任”的论证 |
| 履约能力 | 用实控人控制的、有实际业务的企业来支撑；不利数据（例如净资产为负）不写，先问用户 |
| 潜在责任 | 没获奖励写“0元”；对方尚未主张的写“尚未主张”，不写“较小” |
| 正文不放风险测算和反驳 | 风险测算、对对方函件的逐点反驳、【请…】提示不进正文，风险写进给用户的回复 |
| 内核文件 | 底稿目录按定稿状态；查验计划、底稿目录只一段；签字图片保留 |
| 网络核查笔录 | 只按网核信息表 |
| 比例 | 全文两位小数 |

## 十一、AI 内部工作提示词

**B0 读通知、拆题**
```
把《专项核查通知》拆成表：问题编号 | 原文 | 审核员真正要的结论 | 需要的事实 | 事实来源（申报文件页码/举报附件/需新取得） | 适用规则。
“审核员真正要的结论”用一句话写，例如“某企业是否实控人控制、是否已披露”“实控人违约责任是否会传导到发行人股份”。
再把举报材料逐句拆开，每句标出：可证实的事实部分、定性或推断部分。“举报事项是否属实”表按这个拆分写。
```

**B1 申报文件检索**
```
在申报文件中检索：举报涉及的每个主体名称、人名、协议名、关键数字。记录每处出现的文件、章节、页码和原文。
留意同一事实在招股书不同章节的数字是否一致（注册资本、持股比例、关联方认定）；损坏或打不开的文件列出来，找替代来源。
```

**B2 起草每一问**
```
每一问按“事实 → 规则 → 对照分析 → 小结”写：
1. 先用表格把事实摆清楚（主体关系、协议条款、履行情况、经营数据），表格只放事实；
2. 再引规则原文（法条、上市规则、准则条款号）；
3. 分析逐点对应审核员的关切，每点开头一句话给结论；
4. 每问末尾“综上，……”一句话回答问题本身。
写完自查：是否回答了问题的全部范围；是否每个事实都能指到底稿。
```

**B3 处理批注**
```
逐条读批注（含锚定原文），列表：批注人 | 锚定原文 | 意见 | 改法 | 是否与已定口径冲突 | 回复文字。
冲突的按默认处理（一般按最新、最高层级的意见），批注回复里写明，同时在给用户的回复里列出请其定。
改完后检查：被改段落前后文、同一事实在其他文件（券商稿/律师稿/查验计划/访谈笔录/承诺函）中的写法是否需要同步。
```

**B4 同步检查**
```
列出本轮所有改动，对每一处回答：律师稿是否同步？券商稿是否同步？核查程序变了没有？变了 → 查验计划、底稿目录、律师工作情况的说明、底稿包同步。访谈笔录、承诺函里有没有同一事实的旧写法？
```
