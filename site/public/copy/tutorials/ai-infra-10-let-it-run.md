# AI基建的第十步：别再继续搭了，让它自己跑起来

前面已经搭了模型、Agent、Mac、MCP、GitHub、远程环境、VPS、本地模型和备份。

做到这里以后，我觉得最重要的反而不是继续装新东西，而是：

**开始自动化。**

AI真正有价值的状态，不是每次都等你打开软件、布置任务，它才开始工作。

而是很多重复工作，系统自己就会跑。

比如：

每天自动检查有没有新的 IPO 问询和回复；

每周自动更新知识库；

自动同步 GitHub；

自动备份 VPS；

自动整理新下载的资料；

定期生成一份新增法规、案例和监管动态摘要。

这些事情有一个共同特点：

**重复、规则明确，而且人工做没有太大价值。**

这类工作最适合自动化。

对律师来说，自动化的重点也不是让 AI “自动出法律意见”。

复杂法律判断、诉讼策略、正式文件定稿，还是应该由律师把关。

真正应该自动化的是前面的机械工作：

**查、抓、存、分、整理、同步、备份。**

例如我有一个 IPO 审核问询知识库。

理想状态不是我每周想起来以后手动更新一次。

而是系统自己检查新增项目，自动下载、整理、生成索引，最后告诉我：

> 本周新增多少项目，主要涉及哪些法律问题。

这时候，知识库才真正开始“活起来”。

GitHub Actions、VPS 定时任务、Agent 的计划任务，都可以用来做这些事情。

但我不建议一开始就搭一套特别复杂的自动化系统。

**先把一个小任务跑稳定，再加下一个。**

先自动备份。

再自动同步。

再自动抓取资料。

最后才把它们串起来。

否则很容易出现一种情况：

系统看起来特别高级，但每天都在修 Bug。

这就本末倒置了。

所以整个《AI基建》系列做到最后，我最想说的是：

**不要为了搭基建而搭基建。**

模型、Mac、MCP、GitHub、VPS，都只是工具。

最终目标只有一个：

**让越来越多重复工作不再需要你亲自启动。**

当你开会、出差、吃饭甚至睡觉的时候，系统还在自动同步、整理、备份和更新资料，这套 AI 基建才真正开始产生价值。

**真正成熟的AI基建，不是你装了多少工具，而是有多少工作已经不需要你操心。**
